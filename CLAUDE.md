# RoarMe · instructions for Claude Code

RoarMe is a public chat app (working name), separate from the THEMADLIONS hub (repository
alexisdigipro-hub/themadlions-projects). Owner: Alex Konstantinidis, film director, not a developer.
Talk to him in Greek, friendly and concrete, no em dashes; the app's own text is English.

- React + Vite, plain CSS in src/styles.css, no UI framework. Dark glass look like the hub's chat:
  round glass buttons, pill fields, soft rounded tiles, the chosen item as lighter glass, orange accent.
- **Never a word with an underline as a button** (Alex, 5 Nov, for every site we make): actions are real buttons, a flat matte glass pill or a round glass icon.
- Data in Supabase: only the `roar_*` tables and the `roar-files` / `roar-avatars` buckets; never touch the
  hub's tables. Every database change goes in supabase/schema.sql, written so it can be run again.
- **How we work** (Alex, 14 Nov, after changes he had not asked for: "how will we understand each other, you do your own freestyle"):
  1. Before writing code, say in one or two plain sentences exactly what will change and where, and start only after he says yes.
  2. Only what he asked: no extra buttons, bars or ideas. An idea of your own goes in the reply as a question, never into the app.
  3. Change what already exists: "this button" means that button, never a new one beside it.
  4. When unsure what he means, ask first; never guess.
- **A sample first, then the app** (Alex, 14 Nov: "can you make me the sample here without changing the app", and he chose the live test page): for any change to how something looks, first publish a live test page (an Artifact) built from the app's real stylesheets (src/styles.css, src/themes-halo.css, src/themes-glass.css) with the real classes, light and dark, at phone width, where he can tap and see the motion, with 2 or 3 versions side by side when there is a choice. Touch the app only after he says to put it in ("βάλ' το"). Say plainly that the page is a sample and not the app.
